Issue #2714: bounded diff preview validation

Regression evidence
- The original snapshot behavior (with only the new metadata schema available
  for imports) fails both new behavioral checks: a 512 KiB tracked blob produces
  an unbounded patch, and 510 changed files produce 510 preview rows.
- The bounded implementation passes these checks. Snapshot/revert still retains
  the large file's contents and all 510 file paths.
- Forced cat-file batch failure falls back to individual reads for small blobs
  only; neither oversized blob is read through the fallback.
- An oversized legacy cache is rejected before JSON parsing. Historical anchors
  rebuild the old diff after the worktree changes. Message title, body and text
  parts survive the legacy summary projection and rebuild.

Synthetic benchmark
Run in a separate process: bun script/benchmark-diff-preview.ts
This exercises 100000 changed-file records and the real preview builder/patch
generation. It is not a measurement of an actual 100000-file repository or Git's
own memory usage. RSS is sampled, not a universal peak-memory guarantee.

Measured on Windows with Bun 1.3.14:
  input records: 100000
  retained rows: 500
  omitted rows: 99500
  serialized payload: 151616 bytes
  elapsed: approximately 19 ms
  RSS before: 58867712 bytes
  sampled peak RSS: 92344320 bytes
