# MiMo Loop Detection

**Кратко**: два детектора и одна обработка. Повторы в цепочке рассуждений ловятся n-gram-детекцией с большим окном и большим N; повторные вызовы инструментов ловятся по подряд идущим одинаковым и периодическим вызовам без проверки прогресса; обработка использует уже существующую в коде трёхуровневую эскалацию (напоминание → перепланирование → остановка). Дополнительная модель не нужна, всё выполняется в agent runtime (`packages/opencode/src/session/`).

Все числа ниже являются отправными точками и требуют калибровки на реальных траекториях.

## 1. Детекция повторов в цепочке рассуждений

Проверяются только reasoning и text, сгенерированные на текущем шаге. Пользовательский ввод и вывод инструментов не подмешиваются. Если провайдер отдаёт только сводку размышлений, проверить можно лишь её.

### Параметры

| Параметр | Значение |
| --- | --- |
| Скользящее окно | последние 8192 токенов детектора (вывод `tokenizeForNgram`: разбиение по пробелам, CJK посимвольно) |
| Длина n-gram | 64 |
| Условие срабатывания | одна и та же n-gram встречается ≥ 3 раз, считается по неперекрывающимся позициям |
| Периодичность | проверка каждые 256 новых токенов; при срабатывании прервать генерацию и вернуть `text-repeat` |

### Реализация

Использовать существующую точку подключения `TextNgramMonitor` к потоку (`checkTextNgram` в `processor.ts` и `max-mode.ts`). Заменить внутренний детектор `detectConsecutiveRepeat` на уже написанный `detectRepeatedNgram(tokens, 64, 3)` и увеличить окно с 500 до 8192. Скользящий хеш (замена `slice().join()` с O(1) на токен) отложен; текущая реализация амортизирует проверку через `MIMOCODE_TEXT_NGRAM_CHECK_INTERVAL` (по умолчанию 256 токенов).

Флаги: `MIMOCODE_TEXT_NGRAM_N=64`, `MIMOCODE_TEXT_REPEAT_THRESHOLD=3`, `MIMOCODE_TEXT_WINDOW_TOKENS=8192`.

### Вне рамок

Без MinHash/Jaccard, без коэффициента покрытия, без исключения блоков кода. Перефразированные повторы пока допускается пропускать.

## 2. Детекция повторных вызовов инструментов

Хранить сигнатуры последних 12 завершённых вызовов. Сигнатура = имя инструмента + аргументы (ключи JSON отсортированы, используется `stableStringify`). Не сжимать пробелы внутри строк и не удалять аргументы. Аргументы участвуют в сравнении: чтение трёх разных файлов подряд повтором не является.

| Тип | Условие |
| --- | --- |
| Подряд идущие одинаковые вызовы | последние 3 сигнатуры полностью совпадают. Соответствует существующему `REPEATED_STEP_THRESHOLD=3` |
| Периодические вызовы | последовательность сигнатур имеет период p ∈ [2, 4], и последние 3p вызовов совпадают позиция в позицию. Пример: read A → grep B → read A → grep B → read A → grep B |

При срабатывании не проверять, изменились ли файлы или результаты тестов. Сразу переходить к обработке из раздела 3.

### Исключения: опрос и повторные попытки (порог смягчён, логирование сохраняется)

> Пока не реализовано. Текущая сборка считает опрос и повторные попытки как обычные вызовы; этот раздел — последующая работа.

- Команды bash, содержащие `sleep`, `wait`, `watch`, `poll`, `status`, `tail -f`, либо инструменты ожидания/мониторинга по своей природе: разрешить 10 вызовов одной сигнатуры или 10 минут суммарно, затем считать подряд идущими одинаковыми вызовами.
- Предыдущий результат был временной сетевой ошибкой (`ETIMEDOUT`, `ECONNRESET`, HTTP 5xx / 429): разрешить 3 повторные попытки с backoff, не учитывая их как повторы.

## 3. Обработка: трёхуровневая эскалация

Использовать существующий механизм (`RECOVERY_PROMPT_MILD/STRONG`, `TEXT_NGRAM_RECOVERY_REMIND/REPLAN`). Оба детектора делят один счётчик, не более 2 восстановлений за один ход пользователя.

| Срабатывание | Действие | Внедряемое содержимое |
| --- | --- | --- |
| 1-е | Напоминание (remind) | Прервать генерацию или приостановить следующий вызов; добавить синтетическое сообщение пользователя с указанием, что повторилось (фрагмент n-gram / сигнатура инструмента и число), и требованием изменить формулировку или действие |
| 2-е | Перепланирование (replan) | Требовать отказаться от текущего подхода, написать новый план и объяснить, что делалось, почему не сработало и чем новый план отличается |
| 3-е | Остановка (terminate) | Опубликовать `Session.Event.Error`, сохранить сделанные изменения, отчитаться о зациклившихся действиях, предпринятых восстановлениях и текущем блокере |

При срабатывании по цепочке рассуждений помечать текущий шаг assistant как error, чтобы `toModelMessages` его пропустил и повторяющийся хвост не попал в следующий запрос. При срабатывании по инструментам никогда не переигрывать вызовы и не откатывать код автоматически.

## 4. Интеграция и логирование

- **В потоке генерации**: n-gram-детекция работает инкрементально; без потока проверять весь вывод после завершения генерации.
- **После завершения шага, перед следующим решением**: обновить окно сигнатур и выполнить проверки на подряд идущие/периодические вызовы. Это место существующего «repeated-step nudge»; провести nudge через трёхуровневую эскалацию и учитывать его в счётчике.

Логировать `loop_detected` (тип, сигнатура или фрагмент, число), `recovery_attempted` (уровень) и `loop_terminated`. Начать с `MIMOCODE_LOOP_MODE=monitor` (только лог), вручную просмотреть траектории срабатываний, затем переключиться на `enforce`. `MIMOCODE_LOOP_MODE` по умолчанию равен `monitor` и действует только на два детектора из этого документа; существующая защита от одинаковых выводов между шагами не затрагивается.

> Не заменять это декодерным `no_repeat_ngram_size`: он блокирует код, пути и другой контент, который законно повторяется, и не имеет отношения к детекции циклов во время выполнения.
