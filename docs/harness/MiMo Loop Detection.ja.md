# MiMo Loop Detection

**一言まとめ**：検出器 2 つ + 処理 1 つ。思考連鎖の反復は大ウィンドウ・大 N の n-gram 検出で捕まえる。ツール呼び出しの反復は連続同一呼び出しと周期的呼び出しで捕まえ、進捗判定はしない。処理はコードに既にある 3 段階エスカレーション（リマインド → 再計画 → 終了）を流用する。追加モデルは不要で、すべて agent runtime（`packages/opencode/src/session/`）で実行する。

以下の数値は実験の起点であり、実トラジェクトリで校正する必要がある。

## 1. 思考連鎖の反復検出

対象は今回生成された reasoning と text のみ。ユーザー入力やツール出力は混ぜない。プロバイダが思考要約しか返さない場合は要約しか検査できない。

### パラメータ

| 項目 | 値 |
| --- | --- |
| スライディングウィンドウ | 直近 8192 検出トークン（`tokenizeForNgram` の出力：空白区切り、CJK は 1 文字単位） |
| n-gram 長 | 64 |
| 発火条件 | 同一 n-gram が ≥ 3 回出現。重複しない位置で数える |
| 検査間隔 | 256 トークン追加ごとに検査。発火したら生成を中断し `text-repeat` を返す |

### 実装

`TextNgramMonitor` のストリーム接続点（`processor.ts` の `checkTextNgram`、`max-mode.ts`）を流用し、内部の検出関数を `detectConsecutiveRepeat` から既存の `detectRepeatedNgram(tokens, 64, 3)` に差し替え、ウィンドウを 500 から 8192 に広げる。`slice().join()` はローリングハッシュに置き換え、1 トークンあたり O(1) にする。

フラグ：`MIMOCODE_TEXT_NGRAM_N=64`、`MIMOCODE_TEXT_REPEAT_THRESHOLD=3`、`MIMOCODE_TEXT_WINDOW_TOKENS=8192`。

### やらないこと

MinHash/Jaccard は入れない。カバレッジ率は計算しない。コードブロックの除外もしない。言い換えによる反復は当面見逃しを許容する。

## 2. ツール呼び出しの反復検出

直近 12 回の完了済みツール呼び出しのシグネチャを保持する。シグネチャ = ツール名 + 引数（JSON キーをソート、`stableStringify` を流用）。文字列内部の空白は圧縮しない、引数は削らない。比較には引数を必ず含める：異なる 3 ファイルを連続で読むのは反復ではない。

| 種類 | 条件 |
| --- | --- |
| 連続同一呼び出し | 直近 3 回のシグネチャが完全一致。既存の `REPEATED_STEP_THRESHOLD=3` に対応 |
| 周期的呼び出し | シグネチャ列に周期 p ∈ [2, 4] があり、直近 3p 回が位置ごとに一致。例：read A → grep B → read A → grep B → read A → grep B |

発火後はファイルやテストの変化を判定せず、そのまま第 3 章の処理へ進む。

### ポーリングとリトライの例外（閾値を緩めるが記録はする）

- bash コマンドが `sleep`、`wait`、`watch`、`poll`、`status`、`tail -f` に一致する、またはツール自体が待機/監視系：同一シグネチャで 10 回または累計 10 分まで許容し、超えたら「連続同一呼び出し」として扱う。
- 直前の結果が一時的なネットワークエラー（`ETIMEDOUT`、`ECONNRESET`、HTTP 5xx / 429）：バックオフ付きリトライを 3 回まで許容し、反復回数に数えない。

## 3. 処理：3 段階エスカレーション

既存の仕組み（`RECOVERY_PROMPT_MILD/STRONG`、`TEXT_NGRAM_RECOVERY_REMIND/REPLAN`）を流用する。2 つの検出器はカウンタを共有し、1 ユーザーターンあたりの回復は最大 2 回。

| 何回目 | 動作 | 注入内容 |
| --- | --- | --- |
| 1 回目 | リマインド（remind） | 生成を中断または次の呼び出しを保留し、synthetic user メッセージを追加：何が反復したか（n-gram 断片 / ツールシグネチャと回数）を示し、言い回しか行動を変えるよう求める |
| 2 回目 | 再計画（replan） | 現在の方針を捨てて新しい計画を書き出し、何をしていたか、なぜ失敗したか、新計画がどう違うかを述べさせる |
| 3 回目 | 終了（terminate） | `Session.Event.Error` を発行し、既存の変更は保持し、ループした行動・試した回復・現在のブロッカーを報告する |

思考連鎖の発火時は当該 assistant ステップを error にマークし、`toModelMessages` がスキップするようにして反復した末尾が次のリクエストに戻らないようにする。ツール反復の発火時は自動再実行も自動リバートもしない。

## 4. 接続点とログ

- **生成ストリーム中**：n-gram 検出をインクリメンタルに実行。ストリームが取れない場合は生成終了後に全体を検査する。
- **ステップ完了後、次の判断の前**：ツールシグネチャのウィンドウを更新し、連続/周期判定を行う。既存の「repeated-step nudge」の位置であり、この nudge を 3 段階エスカレーション経由にしてカウントする。

ログには `loop_detected`（種類、シグネチャまたは断片、回数）、`recovery_attempted`（段階）、`loop_terminated` を記録する。まず `MIMOCODE_LOOP_MODE=monitor` で記録のみ行い、発火トラジェクトリを人手で確認してから `enforce` に切り替える。

> デコード時の `no_repeat_ngram_size` で代替しないこと。コードやパスなど正当に繰り返すべき内容まで遮断し、実行時のループ判定とは別物である。
